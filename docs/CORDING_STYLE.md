## 設計
- 単一責任の原則、DRY原則を遵守する
- React 公式推奨の「UIとロジックの分離」をベースに構成
- なるべくロジックは`utils`で実装を行い、`hooks`は状態管理に専念できるようにする
- コンポーネント分割を行い、UIロジックとゲームロジックをモジュール化

## 可読性への取り組み
- if文の{}を省略しない
- 条件式が複雑な場合は説明変数を作成して可読性を向上
- 肥大化した関数はサブ関数に切り分け
- 早期returnが使える箇所は積極的に使用して

## コメントアウト
- 日本語で記述
- 関数やクラス等にドキュメントコメントを記述する
- ドキュメントコメント以外の通常コメントアウトは原則書かない（関数名などコードだけで意図が伝わるようにする）
- コード上での表現が困難な場合のみ通常コメントアウトを記述する

### テスト方針
- ロジック関連の関数を作成した場合、unitテストも作成する
- ロジックに変更を加えた場合、変更内容に応じてunitテストにも変更を加える
